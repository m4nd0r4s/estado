# W0003: `defer!()` in a state with no outgoing edges

## When

A handler calls `defer!()`, but the machine can never leave the state while it is active. A deferred event is redelivered only when the active configuration changes; if no transition can happen, the event waits in the defer queue until the queue overflows (`defer_cap`, default 8).

Status: emitted. One warning per `defer!()` call, at the `defer` identifier. A machine with errors is not checked, because its handler list is incomplete.

### What counts as an outgoing edge

The check reads the analysed handlers of the machine. A state can leave when any handler of a state "in play" has a `goto!` or a `reenter!()`. Timer events, `#[always]` and `#[on_done]` need no special case: their transitions are the `goto!` of the handlers that serve them. The states in play, while the deferring state `S` is active, are:

- `S` itself;
- the ancestors of `S`, and the root: their transitions exit `S`;
- every state below `S`: the event reaches the active leaf first, and a transition there changes the configuration, which requeues the deferred events;
- when `S` is inside a parallel state, every state below the outermost parallel state: a transition in a sibling region changes the configuration as well.

A `defer!()` is fine whenever one of those has an edge, so it is not reported in a state whose ancestor has a `goto!`.

### What is not checked

The analysis is syntactic and does not know which events reach which arm. A defer next to an edge that only fires for another event (`Ev::Cancel => goto!(..)`, `Ev::Data => defer!()`) is not reported. `goto_dyn!` is not supported yet; once it is, it will count as an edge. The warning W0002 (dead end) is independent: a dead-end leaf with `defer!()` gets both.

## Example

```rust
#[machine(event = Ev)]
mod uploader {
    #[root]
    pub enum Uploader {
        #[initial]
        Idle,
        Stuck,
    }

    #[handlers]
    impl Uploader {
        #[on(Idle)]
        fn on_idle(_cx: &mut Cx<Self>, _event: &Ev) -> Next<Self> {
            goto!(Stuck)
        }

        #[on(Stuck)]
        fn on_stuck(_cx: &mut Cx<Self>, event: &Ev) -> Next<Self> {
            match event {
                Ev::Data => defer!(),   // nothing leaves `Stuck`
                Ev::Start => stay!(),
            }
        }
    }
}
```

## Message

```text
warning: use of deprecated function `uploader::__estado_warnings::W0003_Stuck_0`: estado::W0003: `defer!()` in `Stuck`, which has no outgoing edges: the configuration never changes, so the deferred event is never redelivered (silence with `#[machine(allow(W0003))]`)
```

## Fix

Add a transition out of the state (or of an ancestor) that the deferred event can wait for, or handle the event now instead of deferring it.

## Silencing

Prefer `#[machine(allow(W0003))]`: it generates nothing, whatever the lint level. A warning is reported through rustc's `deprecated` lint, so it also turns into an error under `-D warnings` or `-D deprecated`, and `#![allow(deprecated)]` on the crate or an enclosing module hides every `W` code.
