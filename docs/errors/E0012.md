# E0012: duplicate state name, or a name clashing with an id constant

## When

Two nodes of the machine have the same name, or the same `StateId` constant. State names are unique across all levels so that `goto!(Name)` is unambiguous. A region name also counts: it clashes with a state whose constant is the same (`link` and `Link` both give `LINK_ID`).

The `StateId` constants are associated constants of the root type, named in SCREAMING_SNAKE_CASE with the suffix `_ID` (`Bus::IDLE_ID`). A variant of the root enum with exactly that name (a variant `IDLE_ID` next to `Idle`) would be a variant and a constant at once. That is reported too. Names such as `A` or `IO` are fine: their constants are `A_ID` and `IO_ID`.

## Example

```rust
#[state]
pub enum ActiveSub {
    #[initial]
    Playing,
    Idle,          // `Idle` is also a variant of `Player`
}
```

## Message

```text
error: estado::E0012: duplicate state name `Idle`
  = help: state names are unique in a machine so that `goto!(Name)` is unambiguous; rename one
error: estado::E0012: note: `Idle` is first declared here
error: estado::E0012: the id constant `Bus::IDLE_ID` of state `Idle` is also the variant `IDLE_ID`
  = help: rename the variant: the id constants of the states end in `_ID`
```

## Fix

Rename one of them. Name states in CamelCase, and do not end a state name in `_ID`.
