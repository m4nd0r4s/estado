# E0046: constructor uses what the handler borrows

## When

The closure of a constructor `goto!(T, |old: Exiting![X]| value)` uses a parameter of the handler: the data of its state, its `*Mut` view or a `*Fields` of an ancestor. The constructor runs after the handler returned (spec 5.3 step 5), when those borrows are gone; without this check rustc reports an opaque-type lifetime error (E0700) whose advice cannot be followed.

The check follows scopes: a name that a `let` (in the handler before the `goto!`, or in the closure), a closure parameter, a match arm or an `if let` binds again is a different value and is not reported, and neither is a field (`report.up`) or a named argument (`format!("{up}", up = ..)`) that shares the name. A use of the parameter itself, in any form (`up.rounds.clone()`, `f(&up.rounds)`, inside a nested closure or the arguments of a macro), is.

The same rule applies to locals: the closure must not borrow them (rustc E0597); make it `move`.

## Example

```rust
fn running(up: ActiveFields<'_>, event: &Ev) -> Next<Self> {
    goto!(Failed { code: 1 }, |old: Exiting![Active]| Player::Failed {
        code: *up.rounds,          // `up` is borrowed by the handler
    })
}
```

## Message

```text
error: estado::E0046: the constructor of this `goto!` uses `up`, which the handler borrows
  = help: the constructor runs after the handler returned: copy what it needs into a local before the `goto!` and use a `move` closure
```

## Fix

Copy the value into a local before the `goto!` and use a `move` closure:

```rust
let rounds = *up.rounds;
goto!(Failed { code: 1 }, move |old: Exiting![Active]| Player::Failed { code: rounds })
```

The `old` parameter already holds the data of the state that exits, so most constructors need nothing else.
