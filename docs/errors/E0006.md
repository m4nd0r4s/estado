# E0006: handler parameter not recognised

## When

A handler parameter is not one of the accepted kinds, is out of order, is repeated, or names the wrong state's view. Parameters are recognised by type, all optional, in this order: the data of the state itself (`&mut T` or `<Variant>Mut<'_>`), the `<Struct>Fields<'_>` of its ancestors (nearest first), `&mut Cx<Self>`, `&Event`. Handlers are associated functions without a `self` receiver; a compound state's own handler takes its `*Fields`, never `&mut` to the whole struct.

## Example

```rust
fn idle(_event: &Ev, _cx: &mut Cx<Self>) -> Next<Self> { /* .. */ }   // `cx` comes before the event
```

## Message

```text
error: estado::E0006: parameter is out of order or repeated
  = help: parameters come in this order, all optional: own data, ancestor `*Fields` (nearest first), `cx`, event
```

## Fix

Reorder the parameters, remove the unknown one, or take the view the help names (`PlayingMut<'_>` for a struct-like variant, `ActiveFields<'_>` for a compound ancestor).
