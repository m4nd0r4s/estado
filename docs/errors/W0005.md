# W0005: `#[after]` event that no handler handles

## When

An `#[after(duration => event)]` fires an event that no `#[on]` handler can react to, so the timer fires and nothing happens (the machine reports the event as unhandled).

Status: emitted, best effort. The macro reads syntax only, so the rule is built to avoid false positives: **when in doubt it does not warn.** It warns only when all of these hold.

1. **The event names a variant.** The expression (or the body of a closure, or what it calls) is a path of at least two segments whose last segment is CamelCase: `Ev::Timeout`, `Ev::Retry(n)`, `Ev::Expired { id }`, `|s: &S| Ev::Expired(s.id)`. A function call (`make_timeout()`), a constant (`TIMEOUT`), a single segment (which may be an import, `Timeout`) and any other expression are not checked.
2. **Every `#[on]` handler that can see the event is understood.** These are the handlers of the timed state, of its ancestors, of everything below it, and, when it is inside a parallel state, of everything below the outermost parallel state (the same states as W0003). A handler is understood when its event parameter is used only as the scrutinee of `match` expressions (`match event`, `match *event`, `match &event`), and each arm pattern is a variant path (`Ev::A`, `Ev::A(_)`, `Ev::A { .. }`, `Ev::A | Ev::B`, an imported `A`), or a catch-all arm (`_` or a binding) whose body is only `bubble!()` or `unhandled!()`.
3. **None of them names the variant**, by its last path segment: `Ev::Timeout` and `Timeout` are the same variant. An arm that names it counts even if its body is `bubble!()`: it is a deliberate decision.

A handler is *not* understood, and therefore silences the warning, when it:

- has no `match` over the event, or ignores the event parameter;
- has a catch-all arm (`_ => goto!(..)`, `other => defer!()`) that does more than pass the event on;
- uses a pattern that is not a variant (a tuple, a literal, a slice);
- uses the event anywhere else (`if let`, `matches!`, a helper call, `event.kind()`).

A state in play with no `#[on]` handler at all does not silence the warning: nothing there reacts to events.

The span is the variant identifier inside the attribute.

## Example

```rust
#[root]
pub enum Client {
    #[initial]
    Idle,
    #[after(Duration::from_secs(3) => Ev::Timeout)]   // nothing matches `Timeout`
    Connecting,
}

#[handlers]
impl Client {
    #[on(Connecting)]
    fn on_connecting(_cx: &mut Cx<Self>, event: &Ev) -> Next<Self> {
        match event {
            Ev::Start => goto!(Idle),
            _ => unhandled!(),
        }
    }
}
```

## Message

```text
warning: use of deprecated function `client::__estado_warnings::W0005_Connecting_0`: estado::W0005: `#[after]` of `Connecting` fires `Ev::Timeout`, but no handler of `Connecting`, its substates or its ancestors matches it (silence with `#[machine(allow(W0005))]`)
```

## Fix

Add an arm for the variant to a handler of the state or of an ancestor (`Ev::Timeout => goto!(..)`), or remove the timer. If the event is handled in a way the macro cannot see, or the timer is meant to fire unhandled (a test machine, for instance), silence it.

## Silencing

Prefer `#[machine(allow(W0005))]`: it generates nothing, whatever the lint level. A warning is reported through rustc's `deprecated` lint, so it also turns into an error under `-D warnings` or `-D deprecated`, and `#![allow(deprecated)]` on the crate or an enclosing module hides every `W` code.
